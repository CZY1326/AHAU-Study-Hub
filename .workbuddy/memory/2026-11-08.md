**技术关键点（踩过的坑）**

1. **下载链接必须用原生 `<a>` 标签，不能用 Markdown 链接语法。**
   VitePress 会把 Markdown 链接当站内路由解析并做死链检查；
   `.md` 类型的资料会被误判为死链，导致**整个站点构建失败**。原生 `<a href>` 不走路由解析。

2. **原生 `<a href>` 不会被 VitePress 自动拼接 base。**
   base 为 `/AHAU-Study-Hub/`，所以脚本里硬编码了 `BASE` 常量，并用 `encodeURI` 处理中文路径。
   **仓库改名时要同步改两处 base**：config.mts 与 gen-courses.mjs。

3. **VitePress 只发布 `docs/public/` 下的静态资源。**
   课程目录里的 PDF/PPT 默认不进站点，必须构建后显式复制到 `dist/资料/`（即 `--copy` 步骤）。

4. **认知修正：`ignoreDeadLinks: false` 是正确选择。**
   VitePress 的死链检查**本来就只检查站内链接**，外链不受影响。
   曾误以为需要放宽，查阅官方文档后确认 `'localhostLinks'` 仅忽略 localhost，非所需。
   外链质量由 maintenance.yml 的每日巡检独立负责。

5. **自然排序已覆盖文件名层面**：`2-2022年期末真题.pdf` 正确排在 `10-2024年期末真题.pdf` 之前。

**验证方式**：造 9 个测试文件（含中文名 / 数字前缀 / 嵌套目录 / 未知类型 .DS_Store 与 .tmp），

## 追加：2026-11-08 晚 · 线上 404 排查与 CI 修复（已解决）

用户反馈 https://czy1326.github.io/AHAU-Study-Hub/ 返回 404。

### 根因链（连续 5 次部署全部失败）

线上返回 GitHub Pages 官方 "Site not found" 页 → 站点从未发布成功。
通过 GitHub API 逐次追查失败步骤，失败点逐次前移：

| 运行 | 失败步骤 | 原因 |
| :--- | :--- | :--- |
| #1~#3 | `Setup Node`（15~69 秒） | `cache: pnpm` 与 pnpm 11 不兼容 |
| #4 | `Install dependencies` 秒挂 | 移除 cache 后暴露下一层问题 |
| #5 | `Diagnose toolchain` | 我加的 `corepack disable` 把 action-setup 注册的 pnpm 从 PATH 移除，反而阻塞了后续所有步骤 |

**真正的根因**：pnpm + corepack 在 CI 上的多层冲突。
Node 20 默认启用 corepack，会依据 `packageManager` 字段自行下载 pnpm，
与 `pnpm/action-setup` 安装的 pnpm 互相干扰。

### 最终方案：改用 npm（已成功部署）

项目只有 vitepress 一个依赖，pnpm 收益为零、风险却很高。改动：

- 删除 `pnpm-lock.yaml`、`pnpm-workspace.yaml`，新增 `package-lock.json`
- **移除 `package.json` 的 `packageManager` 字段**（这是 corepack 的触发源）
- `deploy.yml` / `maintenance.yml` 改用 `npm ci` + `npm run`
- 诊断步骤一律加 `continue-on-error`，绝不阻塞主流程

**结果**：run on `44897fc` **首次成功**，build 10 步全通过，deploy 成功。

### 关于 Pages 设置的重要发现

排查初期 `/pages` API 返回 404，我误判为"配置了但未生效"。
实际原因是**该仓库从未配置过 Pages**。
而当 `actions/deploy-pages@v4` + `configure-pages` 首次成功运行时，
GitHub **自动创建了 Pages 站点**，且 `build_type` 直接就是 `workflow`。

结论：用官方 action 部署时，**不需要手动去 Settings 选 Source**，会自动配好。
方案原文里"必须选 GitHub Actions"那条针对的是旧式/手动部署路径。

2. **不要引入会阻塞的诊断步骤**。诊断必须 `continue-on-error`，否则它自己就成了故障点。
